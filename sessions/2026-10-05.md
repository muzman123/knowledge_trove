**Section 3: optimizing. Guess first:**

Brute-force two-sum looks like this:

```
for each x in list:
    for each y in list:        ← scans the whole list again, every time
        if x + y == target: ...
```

Inside, the loop is really asking one question over and over.

**What is that question, in plain words? And what tool would answer it instantly?**

> [!quote] YOU · 11:46
> is this pair equal to target? the tool that would answer it instantly im not sure

**CLAUDE · 11:46**

🟨 **True, but the way you phrased it hides the tool.** The trick is to fix one `x` and ask what the inner loop is *really* looking for.

If `x = 2` and the target is `9`, only one partner works: `7`. So the inner loop is asking:

> **"Is `target − x` anywhere in the list?"**

Think of a party where you're looking for Sam. You *could* ask every guest their name, one by one. Or you could check the **guest list at the door**. A **hash set** is that guest list: one $O(1)$ look-up instead of a full scan. That takes the whole thing from $O(n^2)$ down to $O(n)$.

**CLAUDE · 11:55**

🟨 **Question ✓, tool almost there.** You're getting closer each time.

**"How many times"** means you need a **hash map** (a Python `dict`), not a set:
- **Set** = yes/no ("have I seen it?")
- **Map** = key → value ("how many times?" or "at which position?")

Solution: pass 1 counts → `{a:2, b:1, c:2}`. Pass 2 walks the string and returns the first letter whose count is 1 → `b`. $O(n)$.
