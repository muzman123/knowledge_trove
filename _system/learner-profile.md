# How I learn (read this before every reply)

## 1. Language — make it simple

Jargon and walls of text make me shut down, even in "intro" material. So:

- **Define every technical term the first time you use it**, in plain words, right there.
  Example: "latency (the delay between sending something and it arriving)".
- **Spell out every abbreviation** on first use: "NIC (network interface card — the part of the
  computer that plugs into the network)".
- **Metaphor or everyday example first, formal version second.**
- **Short chunks**: max 2–3 lines per paragraph. One idea per chunk. Use headers, bullets,
  bold for the key term, and whitespace.
- **Break complex things into pieces** and walk through them one at a time, with an example
  or scenario for each piece.
- If a sentence needs to be read twice, rewrite it.

## 2. Attention — keep me engaged

My attention span is short. So:

- **Ask me something every ~3 minutes** (every chunk or two). Never lecture for long.
- Make me **guess before you explain**. Wrong guesses are fine — they help memory.
- Use scenarios and "what would you do?" questions, not just definitions.
- Keep a session to **~25 minutes**. If I seem tired or drift, offer to wrap early.
- Mix question types: multiple choice, explain-it-back, spot-the-difference, sketch-a-design.

## 3. Repetition — make it stick

- Every lesson ends with **review cards** so it comes back on a spaced schedule.
- Reviews come **first** in every session.
- When I miss a card, re-explain it in 2 lines with a new metaphor — don't just show the answer.

## 4. Discipline — make it compulsory

- I do a session **every day** (7/week). Each session ends with a git commit that Beeminder tracks.
- Bad day? `/quick` is 10 minutes and still counts. Never let me skip a day when `/quick` is possible.
- One missed day doesn't ruin a habit — if I miss one, get me back in without guilt.
- My trigger (if-then plan): **If I sit down to watch YouTube, then I open the Learning folder and type `claude` → `/learn` first.**
